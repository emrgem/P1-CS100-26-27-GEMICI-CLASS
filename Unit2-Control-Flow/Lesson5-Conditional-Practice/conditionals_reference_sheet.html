Conditionals — if / elif / else · and / or / not

CS100: Roadmap to Computing · Unit 2, Lessons 1–3 · Master Reference Sheet

1. Comparisons produce a value

OperatorMeans
==equal to
!=not equal to
<less than
>greater than
<=less than or equal
>=greater than or equal
health = 24

print(health < 30)
# True

print(type(health < 30))
# <class 'bool'>

A comparison is not magic punctuation. It is an expression, exactly like 2 + 2 — it produces a value. That value is a bool.

2. Named booleans

is_hurt     = health < 30
has_shield  = shields > 0
can_afford  = coins >= 300

Nothing new syntactically — just assignment. But a name changes how you think about the value.

PrefixUse for
is_a state — is_hurt, is_banned
has_possession — has_shield, has_wins
can_ability — can_afford, can_post

The name should read back as a yes/no question.

hurt = health < 30 could be holding anything. is_hurt can only hold an answer. It is a convention, not a rule — Python won't stop you — but it is the convention you are graded on.

3. if / else anatomy

if is_hurt:
    print("Low health!")      # body
    print("Find a medkit")    # also body
else:
    print("You're fine")

print("Match continues")         # not indented - always runs
TermMeans
headerthe if line — ends with :
bodythe indented lines under it
branchone path through the whole thing
Exactly one branch runs. Never both. Never neither.

Indent is 4 spaces — PEP 8, never tabs. The indentation is the block. There is no closing marker.

4. Decide, then use

if kills >= 10:
    rank = "MVP"
else:
    rank = "Player"

print(f"Rank: {rank}")
Branches decide a value. Code after them uses it. Print once.

Printing inside both branches means writing it twice, and it will drift out of sync the first time you change the wording.

= assigns. == compares. if health = 30: is a SyntaxError. Other languages allow it; Python is protecting you.

5. elif — more than two options

if xp >= 5000:
    role = "Legend"
elif xp >= 1000:
    role = "Veteran"
else:
    role = "Member"
KeywordCondition?Position
ifYesstarts the chain
elifYesmiddle — many allowed
elseNolast — optional
All three keywords sit at the same indent and all end with :. An indented elif is a SyntaxError — it lands inside the body, and a body can't hold half a chain.

elif means "otherwise when". Read the whole chain aloud as one sentence and it becomes obvious.

6. First match wins

xp = 7500

if xp >= 1000:      # this wins
    role = "Veteran"
elif xp >= 5000:    # unreachable
    role = "Legend"
else:
    role = "Member"
No error. No warning. Just a wrong answer — a logic error. That is the worst kind, because nothing tells you it happened.

Python checks top to bottom, takes the first true branch, and skips every one after it.

7. Ordering rules

Overlapping branches — order matters

  • Most specific first
  • Most general last
  • Counting down → start with the biggest
  • Counting up → start with the smallest

No overlap — order doesn't matter

if cmd == "heal": ...
elif cmd == "attack": ...
elif cmd == "flee": ...

"heal" is only ever "heal". Shuffle these and it still works.

Order matters only when branches overlap — when one value could satisfy two conditions at once. 7500 is both "over 1000" and "over 5000". A command string is exactly one word.

8. Boundaries — > vs >=

if xp > 1000:
    role = "Veteran"
Expression99910001001
xp > 1000FFT
xp >= 1000FTT
> and >= give different answers for exactly one number: the threshold itself. Every other input behaves identically, so a mistake here only shows up if you test the edge.

Test 499 and 500, not 250. A boundary value is the number sitting right on the threshold.

9. Chain, or separate ifs?

Alternative answers to one question → chain

if score >= 90:    grade = "A"
elif score >= 80:  grade = "B"
else:               grade = "F"

Two independent things → separate ifs

if is_veteran:
    badge = " *"
else:
    badge = ""

if has_wins:
    ranked = "Eligible"
Chain these two and badge steals the whole chain. When is_veteran is True the second check never runs — and you get an eligible player marked ineligible.

10. and / or / not

# both must be true
can_play = is_veteran and has_wins

# either one is enough
is_blocked = is_banned or is_muted

# flip one answer
can_post = not is_banned

Python spells these as words. There is no &&, no ||, no ! — those are SyntaxErrors here.

and and or join two answers. not works on one.

11. The truth tables

and — demanding

True and TrueTrue
True and FalseFalse
False and TrueFalse
False and FalseFalse

Only one row is True.

or — generous

True or TrueTrue
True or FalseTrue
False or TrueTrue
False or FalseFalse

Only one row is False.

12. Precedence — which runs first

not — tightest
and — next
or — loosest

Same idea as * before +. Your eyes read left to right; Python does not.

is_veteran = True
has_wins   = False
is_banned  = True

print(is_veteran or has_wins and not is_banned)
#       True    or (False   and False)
#       True    or  False
#       True
If you have to think about it, write the parentheses. Any time and and or appear in the same expression, parenthesise the and. It costs two characters and removes the doubt.

13. The classic trap

if xp == 1000 or 2000:    # always True
    print("Round number!")

Python reads it as (xp == 1000) or (2000) — and 2000 on its own is truthy.

if xp == 1000 or xp == 2000:  # works
    print("Round number!")
Repeat the variable. A condition with no comparison in it isn't testing anything — it's just a value, and Python reads it as True or False.

14. Truthy and falsy

print(bool(1))       # True
print(bool(0))       # False
print(bool("nova"))  # True
print(bool(""))      # False

These are not comparisons. Nothing is being compared — Python simply has an opinion about each value.

FalsyMeaning
0the number zero
""the empty string
Falsethe boolean itself
Nonethe "no value" value

Everything else is truthy. That is the whole falsy list this year.

15. Three ways to ask "is it empty?"

if username == "":True when it is empty
if not username:True when it is empty
if username:True when it is not empty
The third one flips. Swap it in without also swapping your branches and the program does the opposite of what you meant — with no error to tell you. All three are correct Python; only one means what you want.

16. Which form to use

# text - use truthiness
if username:
    ...

# numbers - be explicit
if coins > 0:
    ...
Why the difference? An empty string means "nothing here", so truthiness says exactly what you mean. But 0 is a real number — zero coins, zero wins, zero lives — and if coins: quietly treats it as nothing at all.

17. Short-circuit — and why it saves you

and stops at the first False. or stops at the first True. Once the answer is certain, the rest of the condition is never looked at. This is called short-circuit evaluation.

Crashes

wins = 0

if score / wins > 100 and wins > 0:
    ...        # ZeroDivisionError

Safe

wins = 0

if wins > 0 and score / wins > 100:
    ...        # never divides

Same two checks, opposite order, and only one of them runs. Put the cheap, protective test first and the one that could fail second. You will use this pattern constantly.

18. or gives back a value, not just True

username = input("Username: ")
display_name = username or "Guest"

If the user typed nothing, username is falsy, so or hands back "Guest" instead. A very common Python habit for filling in a default.

Not safe on numbers. lives = lives or 3 silently turns 0 lives into 3, because 0 is falsy. Same zero trap as section 16.

19. Words you should be able to define

TermMeans
boolean A value that is either True or False.
condition An expression that evaluates to True or False.
comparison operator == != < > <= >= — compares two values, produces a bool.
header / body The if line (ends with :) / the indented lines under it.
branch One path through an if/else.
chain An if with one or more elifs.
logic error Runs fine, wrong answer, no message.
unreachable A branch no input can ever reach.
boundary value The exact number sitting on a threshold.
compound condition Two or more conditions joined with and or or.
truthy / falsy A value Python treats as True / False inside a condition.
short-circuit Python stops evaluating as soon as the answer is certain — which is what lets an earlier test guard a later one.
precedence not before and before or.
